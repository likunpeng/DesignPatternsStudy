命令模式教程

命令模式解决的是"希望把请求发送者和请求接收者解耦，并且支持请求的排队、撤销、日志记录等操作"的问题。它把请求封装成对象。

行为型模式 Command Pattern TypeScript + Python 请求封装

今日目标

  • 理解命令模式解决的问题。
  • 知道什么时候应该把操作封装成命令对象。

  • 能用 Python 实现命令模式。
  • 知道命令模式的适用和不适用场景。

1. 这个模式解决什么问题

把"执行操作"封装成对象后，可以：

  • 把命令存入队列，按顺序执行
  • 记录命令历史，支持撤销/重做
  • 把命令发送给远程服务执行
  • 日志记录命令执行

这样调用者不需要知道具体怎么执行，只管发命令。命令模式最常见的落地场景就是文本编辑器、快捷键系统和任务队列。

2. 一个生活类比

餐厅点餐：顾客只管下单（命令），不需要知道厨师怎么做菜（接收者）。服务员把订单写成单据（命令对象），厨房按单据执行（命令队列）。如果要取消某道菜，只要把对应单据撤掉。

3. 适用场景

  • 需要支持撤销/重做操作。
  • 需要把操作排队、按顺序执行。
  • 需要日志记录操作。
  • 需要把请求发送者和接收者解耦。
  • 事务操作，支持回滚。

4. 不适用场景

  • 操作很简单，不需要队列、撤销等功能。
  • 不需要解耦调用者和执行者。

5. 核心结构

角色职责
Command定义命令接口，通常包含 execute 和 undo。
ConcreteCommand绑定接收者，保存执行所需参数，实现具体命令。
Invoker发起命令、记录历史或排队，不关心命令怎么执行。
Receiver真正执行业务动作的对象。

6. 示例代码

下面用电商后台的订单操作举例。运营人员可能批量审核订单、批量发货、批量退款，这些操作需要可追溯、可撤销、可重试。如果直接让按钮调用业务逻辑，后续加审计日志、失败重试、权限校验会很痛苦。

阅读方法：先看 TypeScript 里命令如何封装操作和状态，再看 Python 如何用函数简化相同意图。重点不是类多，而是每个命令独立、可测试、可组合。

TypeScript 示例

interface Command {
  execute(): Promise<void>;
  undo(): Promise<void>;
}

// 接收者：订单服务，真正执行业务逻辑。
class OrderService {
  async approve(orderId: string) {
    console.log(`订单 ${orderId} 已审核通过`);
  }

  async ship(orderId: string) {
    console.log(`订单 ${orderId} 已发货`);
  }

  async refund(orderId: string) {
    console.log(`订单 ${orderId} 已退款`);
  }
}

// 具体命令：审核订单，保存旧状态以便撤销。
class ApproveOrderCommand implements Command {
  private previousStatus = "";

  constructor(
    private orderService: OrderService,
    private orderId: string
  ) {}

  async execute() {
    this.previousStatus = "pending"; // 实际应从数据库读取
    await this.orderService.approve(this.orderId);
  }

  async undo() {
    console.log(`撤销审核：订单 ${this.orderId} 恢复为 ${this.previousStatus}`);
  }
}

// 具体命令：发货订单。
class ShipOrderCommand implements Command {
  constructor(
    private orderService: OrderService,
    private orderId: string
  ) {}

  async execute() {
    await this.orderService.ship(this.orderId);
  }

  async undo() {
    console.log(`撤销发货：订单 ${this.orderId} 标记为未发货`);
  }
}

// 调用者：批量操作管理器，负责执行、记录、重试。
class BatchOperationManager {
  private history: Command[] = [];

  async execute(command: Command) {
    try {
      await command.execute();
      this.history.push(command);
    } catch (error) {
      console.error("命令执行失败，可加入重试队列", error);
    }
  }

  async undoLast() {
    const command = this.history.pop();
    if (command) await command.undo();
  }
}

const orderService = new OrderService();
const manager = new BatchOperationManager();

await manager.execute(new ApproveOrderCommand(orderService, "ORD-001"));
await manager.execute(new ShipOrderCommand(orderService, "ORD-001"));
await manager.undoLast();

好在哪里：每个命令封装了自己的执行和撤销逻辑；批量管理器不关心具体是什么命令；新增批量退款只需要再加一个命令类，不用改现有代码。

Python 示例

Python 里可以用函数和闭包简化命令，不一定非要写一堆类。但当命令需要复杂状态管理时，类仍然更清晰。

from typing import Callable, Awaitable
import asyncio

class OrderService:
    async def approve(self, order_id: str):
        print(f"订单 {order_id} 已审核通过")

    async def ship(self, order_id: str):
        print(f"订单 {order_id} 已发货")

    async def refund(self, order_id: str):
        print(f"订单 {order_id} 已退款")

# 用函数工厂创建命令，适合简单场景。
def create_approve_command(order_service: OrderService, order_id: str):
    async def execute():
        await order_service.approve(order_id)

    async def undo():
        print(f"撤销审核：订单 {order_id} 恢复为 pending")

    return {"execute": execute, "undo": undo}

def create_ship_command(order_service: OrderService, order_id: str):
    async def execute():
        await order_service.ship(order_id)

    async def undo():
        print(f"撤销发货：订单 {order_id} 标记为未发货")

    return {"execute": execute, "undo": undo}

class BatchOperationManager:
    def __init__(self):
        self.history = []

    async def execute(self, command: dict):
        try:
            await command["execute"]()
            self.history.append(command)
        except Exception as e:
            print(f"命令执行失败，可加入重试队列: {e}")

    async def undo_last(self):
        if self.history:
            await self.history.pop()["undo"]()

async def main():
    order_service = OrderService()
    manager = BatchOperationManager()

    await manager.execute(create_approve_command(order_service, "ORD-001"))
    await manager.execute(create_ship_command(order_service, "ORD-001"))
    await manager.undo_last()

asyncio.run(main())

Python 这里用字典返回 execute 和 undo 函数，避免了为每个简单命令写类。当命令内部需要共享状态、缓存连接或注入 SDK 客户端时，再升级成类就行。

7. 优缺点

优点缺点
发送者和接收者完全解耦类数量增加，每个操作都要一个命令类
支持撤销、重做、排队、日志如果操作很简单，模式可能过度设计
符合开闭原则，可以新增命令命令对象可能暴露内部实现细节

8. 和相似模式的区别

模式区别
策略模式策略模式侧重于选择算法；命令模式侧重于把操作封装成对象。
责任链模式责任链是让请求在多个处理器间传递；命令模式是让命令排队执行。

9. AI 时代的价值

在 AI 协作编程中，命令模式特别有用：

  • 让 AI 生成的操作可追溯：每个命令记录执行时间、参数、结果。
  • 批量操作更安全：AI 生成一批命令后，可以先预览再执行。
  • 失败重试更简单：命令对象可以序列化存入队列，失败后自动重试。
  • 审计合规：金融、医疗等场景需要完整操作日志，命令天然适合。

10. 练习题

场景：电商后台需要批量审核订单、批量发货、批量退款。这些操作需要可追溯、可撤销、失败可重试。请设计命令结构，并说明为什么不用直接调用业务方法。

参考答案：定义 Command 接口包含 execute 和 undo。为每种操作创建具体命令类（ApproveOrderCommand、ShipOrderCommand、RefundOrderCommand），绑定 OrderService 作为接收者。BatchOperationManager 作为调用者，维护命令历史并支持撤销。新增批量操作只需加新命令类，不改现有代码。这样做的价值是：操作可追溯、可组合、可测试，符合开闭原则。

今日总结

命令模式把每个操作封装成独立的对象，实现请求发送者和接收者的解耦。它是实现撤销/重做、命令队列、日志记录等功能的基础。在 AI 时代，命令模式让操作更可追溯、更安全、更易审计。
