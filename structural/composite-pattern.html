组合模式

组合模式解决的是“树形结构里，单个对象和对象集合能否用同一种方式处理”的问题。它让调用方可以统一对待叶子节点和容器节点。

结构型模式Composite PatternTypeScript + Python树形结构
🔍 概念速览

组合模式把树里的单个对象（叶子）和对象集合（容器）都看成同一种东西，让它们实现同一个接口（也就是它们对外提供的一组相同方法），这样调用方就能统一处理叶子和容器，不必写一堆 if 判断。它专门解决“整体-部分”的层级结构问题。

📦一句话类比

寄快递时，大箱子（容器）里可以放小物件（叶子），也可以再套小箱子（子容器）。不管里面是单个物件还是一堆箱子，都贴同一张面单（统一接口），快递员只管称重，不关心里面是什么。

对照代码：大箱子 = Composite（Folder），小物件 = Leaf（FileItem），同一张面单 = Component 接口（getSize）。

虚线框表示接口；Composite 和 Leaf 都实现 Component，Composite 内部持有若干子 Component（叶子或其它 Composite），Client 只面对 Component，不关心拿到的是叶子还是容器。

今日目标

  • 理解组合模式为什么适合菜单、目录、组织架构。
  • 掌握叶子节点和组合节点的共同接口。
  • 能实现递归计算。
  • 知道透明式和安全式组合的取舍。

1. 这个模式解决什么问题

树形结构中，有的节点是叶子，有的节点包含子节点。如果调用方到处判断 isFolder 或 isFile，逻辑会重复。组合模式让它们实现同一接口。

❌ 反例（不要这样写）

// 调用方到处判断节点类型，重复且难扩展
function totalSize(node: any): number {
  if (node.isFile) return node.size;          // 叶子
  let total = 0;
  for (const child of node.children) {
    total += totalSize(child);                // 容器
  }
  return total;
}

这样调用方必须知道每个节点是文件还是文件夹，新增一种节点类型就要去改所有判断点。第 6 部分用组合模式后，所有节点都实现 getSize()，调用方只管调方法，不用写 if。

2. 一个生活类比

公司组织架构里，员工是叶子节点，部门是组合节点。你可以问一个员工“工资是多少”，也可以问一个部门“总工资是多少”。部门会把所有下级员工和子部门的工资加起来。

3. 适用场景

  • 文件目录、菜单、评论树、组织架构、权限树。
  • 调用方希望统一处理单个对象和对象集合。
  • 操作天然具有递归特征，例如统计、渲染、搜索。
  • 树结构层级可能不断变化。

4. 不适用场景

  • 数据不是树形结构。
  • 叶子和容器差异很大，强行统一接口会很别扭。
  • 需要频繁跨层级复杂查询，可能更适合图或索引结构。

5. 核心结构

角色职责
Component叶子和组合节点共同接口。
Leaf没有子节点，直接完成操作。
Composite包含子节点，把操作递归分发给子节点。
Client面向 Component 编程。

6. TypeScript 示例

// 组件接口：叶子和容器共同实现它，调用方只面向这个接口编程
interface FileNode {
  getSize(): number;
}

// 叶子节点：没有子节点，直接返回自身大小
class FileItem implements FileNode {
  constructor(private size: number) {}
  getSize(): number { return this.size; }
}

// 容器节点：持有若干子节点，并把 getSize 递归分发给每个子节点
class Folder implements FileNode {
  private children: FileNode[] = [];

  // 容器特有：把自己的子节点收进来（安全式组合，接口不暴露这个方法）
  add(child: FileNode): void { this.children.push(child); }

  getSize(): number {
    // 递归求和：每个子节点无论是文件还是文件夹，都用自己的 getSize
    return this.children.reduce((total, child) => total + child.getSize(), 0);
  }
}

// 组装树：root 是一个文件夹，里面有一个文件和一个子文件夹 images
const root = new Folder();
root.add(new FileItem(10));
const images = new Folder();
images.add(new FileItem(20));
images.add(new FileItem(30));
root.add(images);
console.log(root.getSize()); // 输出 60（10 + 20 + 30）

Folder 在构造后通过 add() 不断把子节点收进自己的 children 数组，调用 getSize() 时再把这些子节点逐个转发、递归求和。运行会打印：60（10 + 20 + 30）。

7. Python 示例

from typing import Protocol


# 组件接口（协议）：叶子和容器共同实现，调用方只面向它编程
class FileNode(Protocol):
    def get_size(self) -> int:
        ...


# 叶子节点：没有子节点，直接返回自身大小
class FileItem:
    def __init__(self, size: int) -> None:
        self.size = size

    def get_size(self) -> int:
        return self.size


# 容器节点：持有若干子节点，并把 get_size 递归分发给每个子节点
class Folder:
    def __init__(self) -> None:
        self.children: list[FileNode] = []

    # 容器特有：把子节点收进来（安全式组合，叶子没有这个方法）
    def add(self, child: FileNode) -> None:
        self.children.append(child)

    def get_size(self) -> int:
        # 递归求和：每个子节点无论是文件还是文件夹，都用自己的 get_size
        return sum(child.get_size() for child in self.children)


# 组装树：root 是一个文件夹，里面有一个文件和一个子文件夹 images
root = Folder()
root.add(FileItem(10))
images = Folder()
images.add(FileItem(20))
images.add(FileItem(30))
root.add(images)
print(root.get_size())  # 输出 60（10 + 20 + 30）

7.1 透明式和安全式组合的取舍

组合模式在设计时有两种选择：

类型做法适用场景
透明式Component 接口包含 add()、remove()，叶子也实现这些方法（通常抛异常或空操作）。调用方希望统一接口，不关心节点类型。缺点是叶子暴露了不该有的方法。
安全式Component 接口只包含业务方法（如 getSize()），add() 和 remove() 只在 Composite 类中定义。叶子不应该有 add() 方法。缺点是调用方需要知道节点是叶子还是容器。

上面的示例采用的是安全式：FileNode 接口只有 getSize()，add() 只在 Folder 中定义，FileItem 没有 add()。这是更推荐的做法，因为文件不应该有 add() 方法。

8. 优缺点

优点缺点
统一处理叶子和组合节点。接口过于统一时，叶子可能暴露不该有的方法。
递归逻辑清晰，便于扩展节点类型。树很深时要考虑性能和栈深度。
调用方不需要频繁判断节点类型。限制某些节点类型的子节点规则会更复杂。

9. 和相似模式的区别

模式重点区别
组合树形整体和部分一致处理关注节点层级关系。
装饰器一层层增强对象也是递归结构，但重点是增强链，不是树。
迭代器遍历集合可与组合模式配合，但不负责树结构建模。
桥接两条独立维度桥接用「两个不同接口」各自独立变（抽象 ≠ 实现）；组合用「同一个接口」统一处理叶子与容器。两者都靠组合而非继承，所以容易混。易混淆点详见 下方 9.1 节。

一句话区分：简单包装只是套个壳，不改方法也不组织层级；装饰器不改签名，但给对象“加料”（增强功能）；组合则是用同一接口把“整体”和“部分”组织成树，靠递归把所有节点统一处理——它真正的价值在树形层级，而不在外壳。

9.1 特别容易混淆：桥接 vs 组合

桥接和组合都用了「组合」而不是继承，初学者常觉得它们差不多。但只要看意图就分得开：桥接是「两个不同接口各自独立变」，组合是「一个相同接口组成树」。

对比点桥接 Bridge组合 Composite
接口数量两个不同的接口：抽象（Notification）≠ 实现（MessageSender）同一个接口：Leaf 与 Composite 都实现 Component
结构形状一条横线：一个抽象持有一个实现，没有父子层级一棵树：Composite 递归持有同样是 Component 的子节点
解决的问题两个维度都会扩展，用继承会爆炸（M×N → M+N）整体和部分要统一处理，不想写一堆 if 判断节点类型
类比遥控器 + 电视品牌（遥控器不绑品牌，换电视只换实现）大箱子套小箱子/小物件（快递员只管称重，不管里面是箱子还是物件）

快速判别法：拿到需求先问自己——是「一个东西里嵌着另一个不同种类的东西，两边各自会变」？那是桥接。是「一堆同一种类的东西，有的单个、有的抱团，要统一对待」？那是组合。桥接侧的解读见 桥接模式。

10. 练习题

设计一个菜单系统：菜单项可以点击，菜单组包含多个菜单项或子菜单组。请用组合模式实现 render()。

参考思路：定义 MenuNode.render()，MenuItem 渲染自己，MenuGroup 遍历子节点并拼接结果。

今日总结

组合模式的核心是“部分和整体使用同一接口”。只要你的问题是树形结构，并且需要递归处理，就值得考虑它。
